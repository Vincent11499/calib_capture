# calib_capture 使用操作说明

本文只保留日常采集、校验和导出的操作步骤。参数全集见
[reference_config.ini](../script/reference_config.ini)，数据字段见
[DATASET_FORMAT.md](DATASET_FORMAT.md)，AX 接口与 ABI 说明见
[AXERA_IVPS.md](AXERA_IVPS.md)。PC 端 IMU 噪声分析见
[PC_IMU_ALLAN.md](PC_IMU_ALLAN.md)。

## 1. 默认配置

| 项目 | 默认值 |
| --- | --- |
| 左目 | VIN pipe 2 / chn 0 |
| 右目 | VIN pipe 0 / chn 0 |
| 图像接口 | `AX_VIN_GetYuvFrame` |
| 上游格式 | NV12 |
| 分辨率 | 3840×2160，可选 1920×1080 |
| 双目时间差上限 | 200 µs |
| 连续保存频率 | 双目 5 Hz；IMU 全量保存 |
| 图像格式 | 无损灰度 BMP |
| 图像线程 | 2 |
| IMU | `/imu/data`，预期 100 Hz |
| 温度 | `/imu/temperature`，约 1 Hz |
| 输出根目录 | `./data` |

`--resolution` 只核验相机管线的实际输出，不修改管线、不缩放。相机必须事先配置成
3840×2160 或 1920×1080。

4K BMP 数据量较大，60 秒、双目 5 Hz 约需 5 GB。录制前检查剩余空间。

## 2. 板端准备

项目在容器内的默认位置：

```bash
cd /workspace/minsky/Vincent/calib_capture
export BSP_MSP_DIR=/soc/lib
export LD_LIBRARY_PATH=/soc/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}
```

只有使用 IMU 的命令还需要：

```bash
export ROS_DOMAIN_ID=83
source /opt/ros/humble/setup.bash
```

确认相机服务已经启动，并且没有其他程序竞争读取相同 VIN pipe。采集程序不负责启动、
停止或重配相机。

板端只需要项目的 `script/`。ROS1 bag 导出和 Allan 分析在 PC 执行；不要在板端安装新包。

## 3. 首次使用检查

### 3.1 无硬件自检

```bash
python3 script/calibration_data.py self-test
```

用于检查核心逻辑和 ctypes ABI；不证明相机、IMU 或写盘性能正常。

### 3.2 探测双目

4K：

```bash
python3 script/calibration_data.py probe --resolution 3840x2160 --samples 50
```

1080p：

```bash
python3 script/calibration_data.py probe --resolution 1920x1080 --samples 50
```

`--samples` 是探测的双目样本对数，只影响 `probe`，不是录制数量或分频参数。

### 3.3 同时探测 IMU

```bash
python3 script/calibration_data.py probe --resolution 3840x2160 --samples 50 --with-imu
```

该命令确认：

- 左右实际分辨率、格式和源帧率；
- 双目 PTS 差是否不超过 200 µs；
- `/imu/data` 是否可接收；
- 相机与 IMU 时间戳是否位于同一时间域。

`probe` 不保存标定数据。

## 4. 采集命令

所有录制命令默认写入：

```text
./data/<dataset_name>_YYMMDD_hhmm/
```

可用 `--output DIR` 修改根目录，用 `--dataset-name NAME` 修改前缀。录制中目录后缀为
`.inprogress`；成功后提交为正式目录；失败时保留为 `.failed`。

### 4.1 逐姿态双目标定

```bash
python3 script/calibration_data.py stereo-triggered --poses 20 --output ./data
```

每调整一个姿态后按 Enter，程序保存一对图像并等待写盘完成。`q` 中止。未完成指定姿态数时，
数据保留为 `.failed`。

纯双目数据不会创建 `imu/` 目录。

### 4.2 base_link 固定姿态双目采集

```bash
python3 script/calibration_data.py stereo-baselink-triggered \
  --output ./data \
  --resolution 3840x2160
```

该命令固定采集 14 对，不使用 `--poses`。程序会逐次显示当前应拍姿态，按 Enter 后保存：

```text
43_0_0 -> 37_0_0 -> 30_0_0 -> 21_0_0 -> 15_0_0 -> 5_0_0 -> 0_0_0 ->
0_5_0 -> 15_5_0 -> 30_5_0 -> 43_5_0 -> 37_-5_0 -> 21_-5_0 -> 5_-5_0
```

终端会将当前姿态单独放在提示框中，例如：

```text
============================================================
[1/14] 请调整到以下姿态 / TARGET POSE
>>>                 43_0_0                 <<<
============================================================
调整完成后按 Enter 保存（输入 q 退出）:
```

左右图像使用相同姿态名，例如 `cameras/cam0/43_0_0.bmp` 和
`cameras/cam1/43_0_0.bmp`。两侧真实 PTS 仍分别写入 `timestamps.csv`，配对信息仍写入
`meta/pairs.csv`。默认分辨率为 3840×2160，也可显式指定 1920×1080。

### 4.3 连续双目

```bash
python3 script/calibration_data.py stereo-continuous --duration-s 60 --save-rate-hz 5 --output ./data
```

使用 JPEG95：

```bash
python3 script/calibration_data.py stereo-continuous --duration-s 60 --save-rate-hz 10 --image-format jpeg --jpeg-quality 95 --image-workers 4 --output ./data
```

JPEG 有损，适合降低写盘压力；正式标定前应确认 AprilGrid 检测质量。BMP 为默认无损格式。

#### 保存频率与分频

`--save-rate-hz 6` 按相机 PTS 调度，目标周期为 `1/6 s`。源帧每 20 ms 时，实际保存点会落在
第一个达到目标时间的源帧上，因此间隔通常在相邻源帧周期之间交替，不会修改相机帧率。

`--frame-divisor N` 则按源帧序号分频。例如源相机 50 Hz：

| N | 约保存频率 |
| --- | --- |
| 3 | 16.7 Hz |
| 5 | 10 Hz |
| 10 | 5 Hz |

两者不能同时指定。日常优先使用 `--save-rate-hz`，因为含义直接且不依赖源帧率；只有需要严格按
源序号抽样时才使用 `--frame-divisor`。

### 4.4 双目–IMU 联合采集

```bash
python3 script/calibration_data.py stereo-imu --duration-s 60 --save-rate-hz 5 --imu-preroll-s 1 --imu-postroll-s 1 --output ./data
```

`duration-s` 只表示图像录制时长，不包含：

- 图像前的 IMU 前滚；
- 图像后的 IMU 尾采；
- 写盘排空和最终校验。

IMU 始终按收到的消息全量保存，不受 `--save-rate-hz` 或 `--frame-divisor` 影响。第一次
Ctrl+C 停止图像并尝试完成尾采；再次中断会保留失败现场。

### 4.5 USB 单相机采集

USB 图像固定从 `AX_IVPS_GetChnFrame(grp=3, chn=0)` 获取，并严格校验为
1920×1080。脚本不创建或重配 IVPS 管线，不支持 `--resolution`。

连续采集，默认 5 Hz，可使用 `--save-rate-hz` 或等价别名 `--rate-hz`：

```bash
python3 script/calibration_data.py usb-continuous --duration-s 60 --save-rate-hz 5 --output ./data
```

固定 14 个 base_link 姿态逐张采集：

```bash
python3 script/calibration_data.py usb-baselink-triggered --output ./data
```

该模式是单相机数据：只生成 `cameras/cam0` 与 `meta/frames.csv`，不会用同一张图
伪造左右目。固定姿态命令使用 4.2 节相同顺序和姿态文件名。

### 4.6 独立 IMU 和温度采集

用于 Allan 方差分析：

```bash
python3 script/calibration_data.py imu-continuous --duration-s 3600 --imu-topic /imu/data --imu-temperature-topic /imu/temperature --output ./data
```

输出 `imu/imu0.csv`：

```text
timestamp_ns,wx,wy,wz,ax,ay,az,temperature
```

程序按 ROS 回调到达顺序保留每条 IMU。若 `header.stamp` 重复或回退，采集继续，
原始行仍写入 `imu0.csv`，相邻异常详情另写
`meta/imu_timestamp_anomalies.jsonl`；数量和最大回退量写入 session 与 validation。
这类结果用于排查发布端，不能直接送入 Allan 或 Kalibr；分析入口仍会拒绝非严格递增时间戳。
`stereo-imu` 属于标定采集，仍在首个重复或回退处失败，避免静默混入异常 IMU。

角速度单位为 rad/s，加速度单位为 m/s²，温度单位为 °C。每条 IMU 使用当时最新的温度值；
1 Hz 温度在两次更新之间会重复填入，不做插值。数据按 Python `float`（双精度）写出，不主动
取整；原始消息中的精确 0.0 会保留为 0。

长时间 Allan 采集建议设备静止、安装牢固、温度环境稳定，并避免录制期间移动设备。

设备不发布温度时，显式关闭温度订阅：

```bash
python3 script/calibration_data.py imu-continuous --duration-s 900 --imu-topic /imu/data --ignore-temperature --output ./data
```

此时程序不等待 `/imu/temperature`，CSV 为七列
`timestamp_ns,wx,wy,wz,ax,ay,az`。不会用 0、NaN 或虚构温度补列。

### 4.7 实验性逐姿态 RAW

```bash
python3 script/calibration_data.py stereo-raw-triggered --poses 3 --resolution 3840x2160 --output ./data
```

固定调用：

```text
AX_VIN_GetRawFrame(pipe, AX_VIN_PIPE_DUMP_NODE_IFE,
                   AX_SNS_HDR_FRAME_L, ...)
```

该命令只取上游已经配置好的 RAW，不设置 RAW12/RAW16，也不切换压缩模式。它接受 SDK Bayer
格式 `0x80..0x87` 的未压缩或 LOSSLESS 数据，并在元数据中记录实际格式、stride、位深和压缩
模式。RAW 数据不是 Kalibr 图像，不能直接用于标定。

LOSSLESS RAW 必须先用 AXERA 对应版本的解压接口处理。通用 OpenCV 不能直接解压。

### 4.8 PC 端未压缩 RAW 转 PNG

仅适用于已经解压、每像素以小端 uint16 存储的 Bayer 文件。默认参数对应
3840×2160、RGGB、RAW16、小端：

```powershell
python script/raw_to_png.py image.raw
```

默认同时生成：

```text
image.png
image_gray.png
```

彩色图只做 OpenCV 去马赛克；灰度图由去马赛克后的彩色图转换。不会执行黑电平、白平衡、
颜色矩阵、Gamma 或自动拉伸，因此颜色和亮度只用于快速检查。

RAW12 若存放在 16 位容器的低 12 位：

```powershell
python script/raw_to_png.py image.raw --bits 12 --alignment lsb
```

常用参数：

- `--width`、`--height`：图像尺寸；
- `--pattern RGGB|BGGR|GRBG|GBRG`：Bayer 排列；
- `--endian little|big`：字节序；
- `--stride-bytes`：每行实际字节数；
- `--bits 10|12|14|16` 与 `--alignment lsb|msb`：有效位；
- `--png-bits 8|16`：输出位深；
- `--output`：指定彩色输出；灰度文件固定为同名的 `<stem>_gray.png`。

脚本默认拒绝覆盖已有文件。

### 4.9 读取 IMX678 模组 EEPROM

该工具只读 EEPROM，不依赖 Python 第三方包；板端需已有 `i2ctransfer` 命令和对应
`/dev/i2c-N` 访问权限。先做无硬件自检，再按实际总线读取：

```bash
python3 script/read_imx678_eeprom.py --self-test
python3 script/read_imx678_eeprom.py --bus 1
```

辅助输出：

```bash
python3 script/read_imx678_eeprom.py --bus 1 --json
python3 script/read_imx678_eeprom.py --bus 1 --raw
python3 script/read_imx678_eeprom.py --bus 1 --strict-checksum
```

一次读取左右 EEPROM 并分别保存为 `left.yaml`、`right.yaml`（默认左目 `i2c-2`、右目
`i2c-1`，对应左目 VIN pipe 2、右目 VIN pipe 0）：

```bash
python3 script/read_imx678_eeprom.py \
  --yaml-dir ./eeprom_yaml \
  --strict-checksum
```

每个文件用字段名直接保存身份信息、标定时间、图像尺寸、`fx/fy/cx/cy`、RADTAN8 八个
命名系数、标定/验证误差和检测率；不重复生成相机矩阵或第二份畸变向量。校验结果仅保存为
`crc: true/false`。其他接线可用
`--left-bus N --right-bus M` 覆盖。已有文件默认拒绝覆盖，明确需要替换时使用 `--force`。

- 默认 EEPROM 7 位地址为 `0x50`，可用 `--addr` 修改；脚本不会扫描总线。
- `--raw` 输出完整 299 字节十六进制数据；`--json` 输出结构化字段。
- 地址和类型以项目提供的 EEPROM 表为准：有效范围 `0x0000..0x012A`，CRC 位于
  `0x0127..0x012A`。
- 板端实测确认表中的 `CRC_SUM32` 是对 `0x0000..0x0126` 所有字节作无符号累加并
  对 `2^32` 取模，`0x0127` 的存储值为大端；可用 `--strict-checksum` 将不匹配视为失败。
- `i2ctransfer` 命令中的 `w2` 仅设置 EEPROM 的 16 位内部读偏移，并非写入业务数据。

## 5. 使用 INI 配置

日常模板：

```bash
python3 script/calibration_data.py --config script/default_config.ini stereo-imu
```

完整参数参考：

```text
script/reference_config.ini
```

规则：

- 优先级为“命令行 > INI > 内置默认值”；
- `--config` 必须放在子命令前；
- 只接受 `[capture]`；
- 使用 Python 标准库 `configparser`，不依赖 PyYAML；
- `--output`、`probe --samples`、bag 路径等仍是命令行参数。

例如 INI 中为 5 Hz，临时改成 10 Hz：

```bash
python3 script/calibration_data.py --config script/default_config.ini stereo-continuous --save-rate-hz 10
```

## 6. 校验、目录和交付

### 6.1 离线校验

```bash
python3 script/calibration_data.py validate ./data/stereo_260916_1200
```

`errors` 非空表示硬失败；`warnings` 是质量提示。重点查看：

- 左右图像数量、尺寸、解码和时间戳单调性；
- `maximum_stereo_delta_us`；
- `camera_source_sequence_gap_count`；
- `sync_discarded_frames`；
- `rate_limiter_skipped_pairs`；
- `writer_queue_drop_pairs`；
- IMU 频率、长间隔和前后覆盖。

源序号缺口、同步丢帧、限频跳过和写盘丢对是不同统计，不能互相代替。

### 6.2 数据目录

双目数据：

```text
dataset.yaml
cameras/cam0/timestamps.csv
cameras/cam0/<timestamp_ns>.bmp
cameras/cam1/timestamps.csv
cameras/cam1/<timestamp_ns>.bmp
meta/capture_dataset.yaml
meta/pairs.csv
meta/session.json
validation.json
```

联合数据另含 `imu/imu0.csv` 和 `meta/imu_full.jsonl`。根目录
`dataset.yaml` 是严格 Kalibr manifest；完整采集信息在
`meta/capture_dataset.yaml`。具体字段见 [DATASET_FORMAT.md](DATASET_FORMAT.md)。

项目不计算图像 SHA-256；校验结论为结构和解码完整性检查。

### 6.3 PC 导出 ROS1 bag

PC 环境要求 `rosbags==0.11.0`：

```powershell
python script/calibration_data.py export-ros1 data/stereo_imu_260916_1200 data/stereo_imu_260916_1200.bag
```

可选压缩：

```powershell
python script/calibration_data.py export-ros1 DATASET OUTPUT.bag --compression lz4
```

导出器会回读并核对话题类型、消息数、首尾时间戳和单调性。板端不需要 `rosbags`。

## 7. 常见问题

### 加载 AX 库失败

确认在运行 Python 前设置：

```bash
export BSP_MSP_DIR=/soc/lib
export LD_LIBRARY_PATH=/soc/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}
```

这可解决 `libax_engine.so` 加载 `libax_proton.so` 时依赖不可见的问题。

### 分辨率不匹配

脚本不会重配相机。先把相机 config 调整为 4K 或 1080p，再以同样的
`--resolution` 运行。

### 双目同步失败

先执行 `probe`，检查 PTS 单位、源帧率和左右映射。默认只接受不超过 200 µs 的一对。

### 写盘丢对或源序号缺口

依次检查：

1. `writer_queue_drop_pairs` 是否大于 0；
2. 复制和编码阶段耗时；
3. 磁盘空间与写入性能；
4. 是否有其他程序竞争读取 VIN；
5. 降低 `--save-rate-hz`，或 JPEG95 增加到 4 个图像线程。

队列满时程序丢弃完整双目对，不会只保存单侧。

### 收不到 IMU

```bash
ros2 topic list
ros2 topic hz /imu/data
ros2 topic echo /imu/temperature --once
```

检查 `ROS_DOMAIN_ID`、ROS2 环境、话题名和 QoS。

### 数据目录变成 .failed

不要删除。先查看终端错误、`meta/session.json` 和已有文件，再修复原因重新采集。

## 8. 推荐验收顺序

1. `self-test`；
2. 对目标分辨率执行 `probe`；
3. 10 秒短采集；
4. `validate`；
5. 60 秒正式采集；
6. 再次 `validate`；
7. PC 端用 Kalibr reader 或 ROS1 bag 回读；
8. 最后进行 AprilGrid 检测和实际标定。

“目录可读取”只说明格式兼容，不等于标定质量已经通过。

## 9. 采集命令完整参数

本节只列九个采集／探测子命令的有效参数。`validate`、`export-ros1`、`allan` 和
`self-test` 不是采集命令。当前部分子命令因共用解析器，`--help` 可能显示与该模式无关的
参数；不要依赖这些无作用参数。

### 9.1 命令与专用参数

| 子命令 | 用途 | 专用参数 |
| --- | --- | --- |
| `probe` | 探测双目，可同时检查 IMU | `--samples 50`：取样对数；`--with-imu`：同时检查 IMU 和时间域 |
| `stereo-triggered` | 按 Enter 逐姿态保存双目 | `--poses 20`：必须完成的姿态数 |
| `stereo-baselink-triggered` | 按固定顺序采集 base_link 双目 | 固定 14 个姿态，文件名为姿态名；不接受 `--poses` |
| `stereo-raw-triggered` | 实验性 IFE/L RAW 逐姿态采集 | `--poses 20`；仅接受 `--left-pipe`、`--right-pipe`，没有 chn 参数 |
| `stereo-continuous` | 连续双目 | `--duration-s 60`；`--save-rate-hz 5` 或 `--frame-divisor N` |
| `stereo-imu` | 连续双目和完整 IMU | 连续双目参数，另加 `--imu-preroll-s 1`、`--imu-postroll-s 1` |
| `usb-continuous` | IVPS grp 3/chn 0 单路 USB 连续采集 | 固定 1920×1080；`--duration-s 60`；`--save-rate-hz 5`/`--rate-hz 5` |
| `usb-baselink-triggered` | 固定顺序采集 base_link USB 单目图像 | 固定 14 个姿态和文件名；不接受 `--poses`、`--resolution` |
| `imu-continuous` | 独立 IMU，可选温度 | `--duration-s 60`、`--imu-temperature-topic /imu/temperature`、`--ignore-temperature` |

所有命令均支持 `-h/--help`。全局 `--config FILE` 必须写在子命令前，例如：

```bash
python3 script/calibration_data.py --config script/default_config.ini stereo-imu --duration-s 60
```

### 9.2 输出和会话参数

| 参数 | 默认值 | 适用命令 | 说明 |
| --- | --- | --- | --- |
| `--output DIR` | `./data` | 除 `probe` 外的八个录制命令 | 输出根目录；实际创建 `DIR/<dataset_name>_YYMMDD_hhmm` |
| `--dataset-name NAME` | 按模式选择 | 除 `probe` 外的八个录制命令 | 普通双目 `stereo`、base_link `stereo_base_link`、联合 `stereo_imu`、USB `usb`/`usb_baselink`、独立 IMU `imu`、RAW `stereo_raw` |

### 9.3 AX、VIN 与同步参数

| 参数 | 默认值 | 适用命令 | 说明 |
| --- | --- | --- | --- |
| `--ax-lib-dir DIR` | `/soc/lib` | 除 `imu-continuous` | AX 运行库目录 |
| `--sdk-include-dir DIR` | 自动查找 | 除 `imu-continuous` | SDK 头文件目录；找到后执行严格契约检查 |
| `--left-pipe N` | `2` | VIN 双目与 RAW 命令 | 左目 VIN pipe；USB 不使用 |
| `--left-chn N` | `0` | VIN 双目命令 | 左目 VIN channel；USB 不使用 |
| `--right-pipe N` | `0` | VIN 双目与 RAW 命令 | 右目 VIN pipe；USB 不使用 |
| `--right-chn N` | `0` | VIN 双目命令 | 右目 VIN channel；USB 不使用 |
| `--resolution WIDTHxHEIGHT` | `3840x2160` | VIN 相机命令 | 只能为 `3840x2160` 或 `1920x1080`；USB 固定 1920×1080 且不接受此参数 |
| `--expected-source-rate-hz HZ` | `50` | VIN 正式命令、USB 命令 | 质量检查的预期源帧率，不修改生产者帧率 |
| `--sync-tolerance-us US` | `200` | VIN 双目命令 | 左右原始 PTS 最大差，含边界；USB 单路不适用 |
| `--max-sync-retries N` | `10` | VIN 双目命令 | 同步时重取较早侧的最大次数；USB 单路不适用 |
| `--capture-timeout-ms MS` | `200` | 所有 AX 相机命令 | 单次 AX 取帧超时 |

“正式 NV12 相机命令”指 `probe`、`stereo-triggered`、
`stereo-baselink-triggered`、`stereo-continuous` 和 `stereo-imu`；RAW 命令固定使用
IFE/L 接口。

### 9.4 图像保存参数

| 参数 | 默认值 | 适用命令 | 说明 |
| --- | --- | --- | --- |
| `--image-format bmp|jpeg` | `bmp` | 六个正式图像录制命令 | BMP 无损；JPEG 为有损灰度图 |
| `--jpeg-quality N` | `95` | `image-format=jpeg` | OpenCV JPEG 质量，范围 1–100 |
| `--image-workers N` | `2` | 六个正式图像录制命令 | 图像编码／写盘线程数，范围 1–8 |
| `--writer-queue-pairs N` | `2` | 六个正式图像录制命令 | VIN 为双目对队列容量；USB 为单图队列容量 |
| `--save-rate-hz HZ` | `5` | `stereo-continuous`、`stereo-imu`、`usb-continuous` | 按 PTS 保存的目标频率；USB 也接受别名 `--rate-hz` |
| `--frame-divisor N` | `0` | `stereo-continuous`、`stereo-imu` | 按两侧源序号分频；USB 不支持 |
| `--duration-s SEC` | `60` | 三个连续图像命令 | 图像窗口时长；不含联合采集的 IMU 前后滚和排空 |

“六个正式图像录制命令”指 `stereo-triggered`、`stereo-baselink-triggered`、
`stereo-continuous`、`stereo-imu`、`usb-continuous` 和
`usb-baselink-triggered`。RAW 原字节不经过 BMP/JPEG 编码器。

# 双目及双目–IMU 标定数据采集使用操作说明 v1.0.0

软件、CLI、INI 以及项目 JSON/YAML 文档统一版本 `1.0.0`。只支持新契约；旧整数版本和旧目录布局明确拒绝，已有数据不迁移、不改名。字段详情以《目录数据集格式》为准。

## 1. 工具用途

本工具用于：

- 逐姿态采集双目标定图像；
- 定时连续采集双目图像；
- 连续采集双目图像及完整 IMU 消息；
- 校验目录数据集的图像、时间戳、同步、频率和完整性；
- 生成可直接交给 `kalibr-noros` 读取的新目录数据集；
- 将目录数据集离线导出为 ROS1 `.bag`。

采集入口为：

```text
Q:\project\kalibr_cedarobo\script\calibration_data.py
```

板端使用时，应复制整个 `script` 目录，不能只复制入口文件。

## 2. 已确认的相机接口

| 模式 | 输出 | 左目 | 右目 | 接口 | 格式与分辨率 |
|---|---|---|---|---|---|
| cali | VIN | pipe 2 / chn 0 | pipe 0 / chn 0 | `AX_VIN_GetYuvFrame` | NV12；跟随相机 config，正式标定使用 3840×2160 或 1920×1080 |
| vis | VIN | pipe 2 / chn 0 | pipe 0 / chn 0 | `AX_VIN_GetYuvFrame` | NV12，3840×2160 |
| vis | IVPS | grp 7 / chn 0 | grp 8 / chn 0 | `AX_IVPS_GetChnFrame` | 灰度，640×384 |

本工具的标定录制命令读取 cali VIN 输出，不读取 vis 的 640×384 IVPS 输出。

## 3. 开始前检查

开始采集前确认：

1. 相机服务已经根据所需 config 启动 VIN 输出。
2. 左目为 pipe 2/chn 0，右目为 pipe 0/chn 0。
3. 输出格式为 NV12。
4. 输出分辨率为 3840×2160 或 1920×1080。
5. `/soc/lib/libax_sys.so`、`libax_interpreter.so`、`libax_engine.so` 和 `libax_proton.so` 存在；脚本按依赖顺序显式加载这些现有库。
6. 没有其他程序同时消费相同的 VIN pipe/chn 队列。
7. 输出磁盘有足够空间，输出根目录可写；程序生成的时间戳会话目录尚不存在。
8. 采集双目–IMU 数据时，ROS 2 的 `/imu/data` 正在发布，消息时间戳有效。

BMP 图像数据量约为（JPEG 体积取决于画面内容）：

| 模式 | 4K | 1080p |
|---|---:|---:|
| 默认连续 5 Hz、60 秒、双目 | 约 5 GB | 约 1.25 GB |
| 触发保存 20 对 | 约 0.33 GB | 约 0.08 GB |

程序会提示预计数据量，但不会因为剩余容量或写速不足而拒绝启动。

## 6. 首次硬件探测

### 6.1 探测 4K 双目

相机 config 输出 3840×2160 时执行：

```bash
python3 script/calibration_data.py probe --samples 50
```

默认值等价于：

```bash
python3 script/calibration_data.py probe --samples 50 \
  --left-pipe 2 --left-chn 0 \
  --right-pipe 0 --right-chn 0 \
  --resolution 3840x2160
```

### 6.2 探测 1080p 双目

相机 config 输出 1920×1080 时必须显式指定：

```bash
python3 script/calibration_data.py probe --samples 50 \
  --resolution 1920x1080
```

`--resolution` 不会改变相机输出，只负责校验。实际输出不匹配时程序立即失败。

两种分辨率具体由以下代码共同支持：

- `script/calib_capture/cli.py`：提供 `--resolution WIDTHxHEIGHT`；
- `script/calib_capture/config.py`：`parse_resolution()` 只接受 `3840x2160` 和 `1920x1080`；
- `script/calib_capture/axera.py`：`validate_frame_metadata()` 对 `AX_VIN_GetYuvFrame` 返回帧的实际宽高逐帧校验；
- `script/calib_capture/validator.py`：离线检查 BMP 尺寸是否与会话配置一致。

因此“支持”表示脚本能够接收、采集并校验这两种上游输出，并不表示脚本会修改相机 config。

### 6.3 同时探测 IMU

```bash
source /opt/ros/humble/setup.bash
python3 script/calibration_data.py probe --samples 50 --with-imu \
  --imu-topic /imu/data
```

重点检查 JSON 输出中的：

- `status`：应为 `pass`，允许评估后接受 `warning`，不能忽略 `fail`；
- `mapping`：左目 pipe 2、右目 pipe 0、chn 0；
- `actual_resolution`：与相机 config 和命令一致；
- `observed_formats`：左右均应为 NV12；
- `source_rate_hz`：应接近相机预期 50 Hz；
- `stereo_delta_us.maximum`：默认不得超过 200 µs；
- `source_sequence`：检查序号缺口或回退；
- `imu.effective_rate_hz`：应接近 100 Hz；
- `imu.startup_camera_offset_ns`：默认不得超过 5 秒；
- `imu.common_time_window_ns`：应大于 0。

`probe` 未通过时不要直接开始正式标定采集。

## 7. 逐姿态双目标定采集

默认采集 20 个姿态，每次按 Enter 保存一对图像。`--output` 默认是 `./data`，以下显式写出便于说明：

```bash
python3 script/calibration_data.py stereo-triggered --output ./data
```

操作步骤：

1. 将标定板放在第一个姿态，确保左右相机都能清晰看到。
2. 静止后按 Enter。
3. 等待当前双目对写盘完成。
4. 改变标定板的位置、距离、俯仰、偏航和滚转角度。
5. 重复直至保存 20 对。

可指定姿态数量或 1080p：

```bash
python3 script/calibration_data.py stereo-triggered \
  --output ./data \
  --resolution 1920x1080 \
  --poses 20
```

输入 `q`、`quit` 或 `exit` 会中止采集。未完成指定姿态数量时，已采数据保留为 `<output>/<dataset_name>_YYMMDD_hhmm.failed`，不会删除。

## 8. 连续双目采集

默认持续 60 秒，按相机 PTS 保存双目 5 Hz（约 200 ms 一对）：

```bash
python3 script/calibration_data.py stereo-continuous \
  --output ./data \
  --duration-s 60 \
  --save-rate-hz 5
```

1080p 示例：

```bash
python3 script/calibration_data.py stereo-continuous \
  --output ./data \
  --resolution 1920x1080 \
  --duration-s 60 \
  --save-rate-hz 5
```

`--save-rate-hz 5` 可省略。限频以首对 PTS 为起点，选择到达每个目标时刻的第一对。例如源周期为 20 ms，指定 6 Hz 时，相对保存时间为 0、180、340、500、680、840、1000 ms；长期平均接近 6 Hz，图像保留各自原始 PTS。

写盘队列满时会丢弃完整双目对，并在 `meta/session.json` 与 `meta/validation.json` 中记录 `writer_queue_drop_pairs`；不会只保存一侧。

在 `meta/session.json.capture_stats` 分开查看：`source_left_sequence_gaps` / `source_right_sequence_gaps` 是每次成功 VIN 取帧之间实际观察到的序号缺口；`sync_left_discarded_frames` / `sync_right_discarded_frames` 是主动同步淘汰的帧；`rate_limiter_skipped_pairs` 是限频跳过的对，`frame_divisor_skipped_pairs` 是分频跳过的对，`writer_queue_drop_pairs` 是写盘容量不足丢弃的对。预热与 IMU 前滚不计入上述录制窗口；`grabber_stats.sync_retries` 仍含预热，不能拿来相减。旧报告的缺口可能包含同步淘汰，不能直接与新数据比较。详见《目录数据集格式》的统计口径说明。

当前 BMP 保持原 bottom-up 格式，复制 Y 平面时直接形成目标行序，再按大块写入，避免写盘前再次拼接整图。所有数据文件均不计算 SHA-256，停止录制后也不补算。`meta/session.json.write_performance` 保留平均、最大、累计的每对任务延迟；包含图像线程池和有序提交等待，不含输入队列等待、取帧或 fsync。多对并行时累计延迟不是录制墙钟时间，详情见《目录数据集格式》。

### JPEG 压缩保存

在 INI 的 `[capture]` 中设置，默认 BMP 保持不变：

```ini
image_format = jpeg
jpeg_quality = 95
```

也可临时指定：

```bash
python3 script/calibration_data.py --config script/default_config.ini camera-imu --image-format jpeg --jpeg-quality 95
```

质量范围 1–100，默认 95。灰度 JPG 不缩放、不改变时间戳，双目仍 5 Hz、IMU 全量保存。JPEG 有损，角点附近像素可能变化，需用实际标定数据评估；质量数值不是保留像素百分比或固定压缩率。

直接使用现有 OpenCV（cv2）/NumPy 编解码，不使用 Pillow，不安装板端新依赖；缺少编码库时在建立会话目录前报错。BMP 不依赖 JPEG 库。旧图像不会自动转码或删除；`--image-format bmp` 可继续无损保存。

JPEG 默认使用两个复用线程分别 `imencode` 左右图并写临时文件；可用 `--image-workers 4/6/8` 允许多对同时处理，始终按采集顺序提交完整双目对。异常清理必须等相关任务结束。启动提示的 BMP 等效容量不是 JPEG 容量预测。校验通过 `imdecode` 完整解码检查单通道、尺寸、配对与时间戳，不额外复制整图像素 bytes。bag 导出的是解码后 mono8，不是压缩消息，不能恢复原始像素，也不保证与 JPG 同样小。

### 有界并行和内存

`image_workers = 2`／`--image-workers 2` 同时适用于 BMP 和 JPEG，范围 1–8。默认双目仍为 5 Hz，增加线程不会提高目标保存频率；高频探索需要同时显式设置 `--save-rate-hz 20`，不保证达到目标。

一个线程处理一张完整图像，不对单张 JPEG 切块。默认等待队列 2 对，同时处理最多 `ceil(image_workers/2)` 对；完成但尚未按顺序提交的对也占用额度。缓冲池按需分配，可复用槽位上限为等待队列 + 同时处理对数 + 1，不无限缓存。VIN Y 平面只复制到自有缓冲，编码线程不持有 VIN 帧。

CSV 和 IMU JSONL 每 0.5 秒批量刷新；正常停止和可处理异常时全部刷新，不逐帧 fsync。突然断电或强杀可能丢失尚未刷新的记录。IMU 接收数量不受图像限频影响。

`capture_stages`、`image_stages`、`capture_stats.pipeline` 分阶段报告耗时、队列/缓冲高水位及排空时间；另报告 RSS 峰值和校验耗时。看实际 PTS 保存频率、队列丢对和排空时间判断吞吐，不能只看任务提交速度。

### 8.1 按源图像帧分频

`--frame-divisor N` 依据左右帧的 AX `u64SeqNum` 源序号分频。第一对立即保存；以后只有当左右源序号相对上一保存对都至少前进 N 时才保存。跳过操作发生在物理内存映射和 BMP 写盘之前，左右目始终成对处理。

假设 `AX_VIN_GetYuvFrame` 每 20 ms 返回一张：

| 参数 | 保存周期 | 约等于保存频率 |
|---|---:|---:|
| `--frame-divisor 1` | 20 ms | 50 Hz |
| `--frame-divisor 3` | 60 ms | 16.67 Hz |
| `--frame-divisor 5` | 100 ms | 10 Hz |

例如每 3 对保存一对：

```bash
python3 script/calibration_data.py stereo-continuous \
  --output ./data \
  --duration-s 60 \
  --frame-divisor 3
```

`--save-rate-hz` 与 `--frame-divisor` 互斥，推荐使用前者指定目标 Hz；后者适用于固定源周期的整数分频。两者都省略时默认使用 `save_rate_hz = 5`。命令行策略覆盖 INI 配置；INI 的 `[capture]` 中不能同时设置 `save_rate_hz` 和正数 `frame_divisor`，`frame_divisor = 0` 表示关闭分频。源帧缺失或写盘队列丢对会使实际保存间隔变长，相关统计写入 `meta/session.json`。

参数作用域：

| 参数 | 可用命令 | 作用 |
|---|---|---|
| `--samples N` | 仅 `probe` | 连续观察 N 个同步双目对，只做诊断、不落盘 |
| `--save-rate-hz HZ` | `stereo-continuous`、`camera-imu` | 按 PTS 保存接近指定频率的双目对 |
| `--frame-divisor N` | `stereo-continuous`、`camera-imu` | 左右 AX 源序号都至少前进 N 后保存一对 |

逐姿态 `stereo-triggered` 由操作者按 Enter 决定保存时机，不使用上述三个参数。

## 9. 双目–IMU 联合采集

确认相机和 IMU 探测通过后执行：

```bash
source /opt/ros/humble/setup.bash
  python3 script/calibration_data.py camera-imu \
    --output ./data \
    --duration-s 60 \
    --save-rate-hz 5 \
    --imu-topic /imu/data
```

`camera-imu` 默认保存双目 5 Hz，限频只作用于完整双目对。IMU 收到的消息全部保存，不随图像降频。

默认在图像窗口前后各保留至少 1 秒 IMU。`--duration-s 60` 指图像采集 60 秒，不包含前滚、后滚、写盘排空或校验；预计约 62 秒采集，再加启动、收尾和校验耗时。前后覆盖按原始传感器时间戳检查，不以简单等待时间替代。

可以显式调整（仅 `camera-imu`，非负有限秒数，`0` 关闭该侧额外覆盖要求）：

```bash
python3 script/calibration_data.py camera-imu \
  --duration-s 60 --save-rate-hz 5 \
  --imu-preroll-s 1 --imu-postroll-s 1
```

前滚期间继续取出并释放相机帧，不保存预热图像；图像窗口结束后 IMU 继续接收至满足后滚要求。不要在画面采集结束时强杀进程，需等待收尾和校验结束。实际覆盖与超时结果会记录在会话元数据和校验报告中。

原始消息 `header.frame_id` 非空时优先使用，例如 `imu_link`；为空时才回退 `--imu-frame-id`（默认 `imu0`）并告警。JSONL 中的 `frame_id` 保留原始值，包括空串；session 和内部 manifest 单独记录有效坐标系。有效坐标系在会话中发生变化是硬错误，避免混合不同坐标系的 IMU 数据。

默认仍保持 4K、BMP、5 Hz、2 图像线程和 200 µs 双目同步阈值。若重点采集 Camera–IMU 时间偏移数据，可显式提高至 10 Hz；板端曾通过 BMP 2 线程、JPEG95 4 线程的一分钟 10 Hz 测试，详情见《板端验证记录》。这不代表长期无丢帧保证，20 Hz 也不是已达到的稳定目标。

IMU 默认 QoS 为：

```text
BEST_EFFORT + VOLATILE + KEEP_LAST(depth=2000)
```

相机使用各自 `u64PTS × 1000` 纳秒，IMU 使用原始 `header.stamp`。同一启动阶段的相机/IMU参照时间戳差超过 5 秒会拒绝录制；该参照保存于 session，不用主动前滚后的首张保存图像时间来判断时钟域。

## 10. 使用 INI 配置

### 独立 IMU 连续采集（用于后续 Allan 方差）

只需 ROS 2 与 IMU 发布端，不依赖相机、AX 运行库、OpenCV 或 rosbags。例如录制一小时：

```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=83
python3 script/calibration_data.py imu-continuous \
  --duration-s 3600 --imu-topic /imu/data --output ./data
```

`ROS_DOMAIN_ID` 需与实际发布端一致。`--duration-s` 默认 60 秒，必须为有限正数，从收到第一条消息后开始计时，不包括启动等待和校验；以上 3600 秒只是操作示例，不代表 Allan 分析充分性保证。第一次 Ctrl+C 提前结束并保留已收到的数据；无数据或不足两条样本为失败。第二次中断或其他异常保留 `.failed`。

全部收到的 IMU 消息直接写 CSV，不受双目 5 Hz 配置影响；不接受 `--save-rate-hz`、`--frame-divisor` 或相机参数。`--imu-expected-rate-hz` 默认 100，仅用于质量检查，不修改发布频率。其余可用选项：`--imu-frame-id`、`--imu-qos-depth`、`--startup-timeout-s`；启动等待与运行中停流共用该超时（默认 15 秒）。INI 使用现有 `[capture]`，支持 CLI 覆盖。

输出为 `./data/<会话名>/imu/imu0.csv`，表头 `timestamp_ns,wx,wy,wz,ax,ay,az,temperature`。时间戳为原消息整数纳秒，角速度 rad/s，加速度 m/s²，温度为摄氏度；不做降采样、插值、去均值、改轴或单位转换。辅助信息统一在 `meta/session.json`、`meta/validation.json`，记录频率、最大间隔、长间隔和有效 frame ID。每 0.5 秒刷新，结束时最终刷新；突然断电仍可能丢失未刷新的数据，未增加 fsync 或数据 SHA-256。

仅此模式默认新增 `/imu/temperature` 订阅，类型 `sensor_msgs/msg/Temperature`，可用 `--imu-temperature-topic` 或 INI `imu_temperature_topic` 覆盖。每条约 100 Hz 的 IMU 附带最新收到的温度（约 1 Hz），不按温度 header 时间戳做同步；两次更新之间一直沿用旧值。variance 不使用，`.nan` 允许；temperature 本身非有限则报错。

首条温度前的 IMU 不保存、只统计预热跳过数；温度到达后的首条 IMU 才开始录制计时。超过 `startup_timeout_s` 仍没有可保存的 IMU 则失败。温度暂时不更新不会中止采集，沿用超过 2 秒在报告中告警。此变化不影响 `camera-imu` 的七列 CSV；旧七列独立 IMU 文件不会迁移，新校验会明确拒绝列数不符。后续 Allan 分析应选择前七列或按列名读取，温度单独用于分析温度相关性。

独立数据可用 `python3 script/calibration_data.py validate ./data/<时间戳>` 重新流式校验；不生成相机目录、双目 Kalibr manifest 或 IMU JSONL，不支持本工具的 ROS1 bag 导出。后续 Allan 工具的输入约定若不同，需按其列顺序、时间单位适配；本命令只负责原始数据采集，不计算 Allan 方差，也不自动判定静止状态或数据是否适合分析。

### PC 离线 Allan 方差分析

指定 `--start-s/--end-s` 时，默认结果名追加小时区间：`imu_260911_1502_1h-24h`。小时为整数时不带小数，否则四舍五入保留一位（如 `_1.5h-5.2h`）；仅省略起点用 `0h`，仅省略终点用 `end`。不指定时间则仍用输入目录名。名称舍入不改变实际选区，精确秒数见报告；不同选区舍入同名时不会覆盖，需显式指定不同 `--output`。显式 `--output` 始终作为完整路径，不再追加后缀。

将完整的独立 IMU 会话目录复制到 PC，保留 `imu/imu0.csv` 和 `meta/`。新增 `allan` 命令直接读取八列 CSV，不需要手工转换列名；不接受双目联合采集目录或任意裸 CSV。采集命令本身仍不计算 Allan 方差。

在 PC Python 环境准备可选依赖（以下安装由使用者自行决定，程序不会自动安装）：

```bash
python -m pip install -r script/requirements-allan.txt
```

从项目顶层运行，目录名替换为实际采集目录：

```bash
python script/calibration_data.py allan ./data/imu_260911_1400
# 独立脚本入口，效果相同：
python script/analyze_allan.py ./data/imu_260911_1400
```

默认输出到项目根目录下 `data/allan_variance/allantools_output/<输入目录名>/`，例如 `data/allan_variance/allantools_output/imu_260911_1400/`，不受启动工作目录影响，不修改原始目录。显式 `--output PATH` 覆盖完整结果目录，相对 PATH 按当前工作目录解析，不再自动追加输入名。生成六个 `allan_wx.csv` 至 `allan_az.csv`、`allan_deviation.png`、`allan_variance.png` 和 `analysis.json`。CSV 列为 `tau_s,adev,avar,adev_error,n`，其中 `avar = adev²`；角速度标准差单位 rad/s，加速度标准差单位 m/s²，方差单位分别平方。结果先写 `.inprogress`，完成后改名；失败保留 `.failed`，已存在的输出不覆盖。

参数仅通过 CLI 设置，不加入采集 INI：

| 参数 | 默认与作用 |
|---|---|
| `--output PATH` | 指定独立的新结果目录，不得与原始会话目录重叠 |
| `--rate-hz HZ` | 默认按 `(样本数−1)/(末时间−首时间)` 推算实际频率；只在确认采样率后显式覆盖 |
| `--taus decade` | 平均时间取点策略，可选 `octave` |
| `--start-s SECONDS` | 起点，默认 0；相对原始 CSV 第一条 IMU 时间戳，包含起点 |
| `--end-s SECONDS` | 终点，默认录制末尾；同样相对第一条 IMU，不包含终点 |
| `--allow-irregular` | 显式允许将非均匀样本近似当作等间隔数据；结果会告警，不插值 |

例如跳过开头 1 小时，只分析第 1–24 小时：

```bash
python script/analyze_allan.py data/allan_variance/data/imu_260911_1502 --start-s 3600 --end-s 86400 --allow-irregular
```

区间为 `[start, end)`，不是系统日期时间，也不是图中平均时间 tau。起点必须为有限非负数，终点必须为有限数且大于起点；终点超过录制末尾时取到末尾，选中不足四条样本报错。省略两项分析全段。指定区间自动追加小时后缀，示例输出 `imu_260911_1502_1h-24h`；同名已有结果仍拒绝覆盖。`analysis.json.selection` 记录请求范围、实际首末时间戳、原始/选中数量及两端排除数量；频率、温度、六轴和曲线均只使用选中段。仍先检查完整源数据结构，选区不能绕过源文件错误；不会改写 CSV、插值或剔除选中段内样本。

时间戳按 int64 纳秒读取，六轴按 float64 计算。至少四条样本，先检查源目录结构、有限值和严格递增时间戳。任一间隔相对分析周期偏差超过 10% 时默认拒绝；10% 是本工具诊断阈值，不是科学有效性保证。先检查丢样、时间基准和抖动原因，不应为得到曲线直接忽略警告。

调用 [AllanTools oadev](https://allantools.readthedocs.io/en/latest/functions.html#allantools.oadev)，使用 `data_type="freq"` 直接处理角速度和加速度，不先积分、不归一化；`n` 是计算项数量，不表示独立样本数。温度仅记录最小、最大、平均值，不参与六轴计算。正常的零值保留，不当作缺失值。

分析会加载完整时间序列，内存随录制长度增长，但不依赖 ROS、AX 或 rosbags。应使用静止、温度稳定且无明显物理异常的记录；不会自动删除离群值或认定数据合格，报告保留质量提醒。默认只计算曲线，可用下面的 `--kalibr-noise` 显式拟合；曲线最低点不能直接当作 random_walk，参见 [Kalibr 噪声模型](https://github.com/ethz-asl/kalibr/wiki/IMU-Noise-Model)。

### 导出 Kalibr IMU 噪声文件

```bash
python script/analyze_allan.py data/allan_variance/imu_260911_1502 --start-s 3600 --end-s 86400 --taus octave --allow-irregular --kalibr-noise --output data/allan_variance/allantools_output/imu_260911_1502_noise_1h_24h
```

`--kalibr-noise` 在选中时间段的六轴 Allan 标准差曲线上拟合。白噪声固定斜率 -1/2，取拟合线 tau=1 s 的值；偏置随机游走固定斜率 +1/2，取 tau=3 s 的值（包含 sqrt(3) 系数）。这不是把实测 tau=1/3 s 的点直接填入，也不是使用曲线最低值。

自动选段是保守的工程启发式，不是置信区间：至少 4 个连续点、跨度至少 0.7 个数量级、自由拟合斜率偏差不超过 0.15、相邻点斜率偏差不超过 0.3、固定斜率 log10 RMSE 不超过 0.08，且 tau 不超过选中时长的 1/10。候选中优先最长跨度，再选较小误差。Allan 重叠项数量不能当作独立样本数。可选 `--taus octave` 增加取点，但不能替代长时间数据或绕过选段要求。

只有六轴的两类参数均可拟合，才生成 `kalibr_imu.yaml`，包含 `gyroscope_noise_density`、`gyroscope_random_walk`、`accelerometer_noise_density`、`accelerometer_random_walk`、`update_rate`、`rostopic`。每类取对应三轴最大值，无额外安全倍率；update_rate 为实际用于分析的频率。rostopic 默认 `/imu/data`，可用 `--kalibr-imu-topic /custom/imu` 覆盖。Kalibr no-ROS 的目录任务不靠 topic 关联传感器，仍需在 task 中正确指定 IMU ID。

`analysis.json.noise_fit` 保存每轴区间、斜率、残差、参数、聚合规则和 YAML 路径。拟合完整时状态为 `candidate`，仍需人工审查静止性、温漂和标定表现；不同轴明显各向异性时，单一参数模型也需评估。不齐全时为 `incomplete`，列出缺失项，不生成 YAML，保留曲线和报告，命令退出码为 1；不以 0、最低点或其他轴冒充缺失值。文件是噪声模型配置，不是 IMU 内参或相机–IMU 外参标定结果。

### 可选：ROS1 imu_utils 交叉分析

此外部工具只读取八列 imu/imu0.csv，不要求或读取输入元数据；--frame-id 默认 imu_link。详细文档包含进入 Docker 后的逐步转换、回放、绘图命令。

需要使用原版 ROS1 `imu_utils` 的五项噪声模型拟合时，参见
[《ROS1 imu_utils 容器与分析说明》](IMU_UTILS.md)。该流程在 PC 的长期 Noetic 容器中
运行，把独立 IMU CSV 转成仅供 `imu_utils` 回放的派生 bag；原会话保持只读，所有 bag、
TXT、YAML、PNG、日志和报告写入独立的 `data/allan_variance/imu_utils_output/<会话名>/`。

派生 bag 必须逐条回读，确认 `/imu/data` 的消息数量、时间戳和六轴值与 CSV
一致。高速回放完成后，六个轴的 `numData` 必须全部等于 bag 消息数；存在丢消息的运行
只能放入 `diagnostic_*`，不能输出为最终参数。本机 `imu_260910_2209` 已采用 100 倍速和
`--queue=1000000` 完整消费 1,447,587 条消息，并生成实测/拟合曲线及中文报告。

`imu_utils` 的 `gyr_w`、`acc_w` 表示其拟合曲线最低值对应的 bias instability，不是
Kalibr 的 bias random walk。不得按字段名直接复制到 Kalibr IMU YAML；仍需依据 Kalibr
定义的 `-1/2`、`+1/2` 斜率段和单位提取参数。

### INI 配置用法

精简模板位于 `script/default_config.ini`；完整参数参考位于 `script/reference_config.ini`，包含全部可加载项、单位、作用域以及 CLI 专用选项注释，两份模板的有效默认配置一致。使用 Python 标准库 `configparser` 读取，无需安装配置解析库。注意：`--config` 是主命令参数，必须写在子命令之前。

正确示例：

```bash
python3 script/calibration_data.py --config script/default_config.ini camera-imu \
  --output ./data \
  --resolution 1920x1080
```

错误示例：

```bash
python3 script/calibration_data.py camera-imu --config script/default_config.ini
```

配置优先级为：

```text
命令行参数 > INI [capture] 配置 > 程序内置默认值
```

不写 `--config` 时，不会自动读取模板。采集参数只从 `[capture]` 段读取，未写的参数使用内置默认值。精简模板只保留分辨率、双目同步阈值、图像格式、JPEG 质量、图像线程数、保存频率、时长、姿态数和 IMU 话题；cali/vis 接线清单见第 2 节。SDK 路径、接线、超时、队列、QoS 和输出话题等高级参数见完整参考 INI，仍可通过 CLI 覆盖（查看 `camera-imu --help`）。例如最小配置：

```ini
; 双目 5 Hz，IMU 收到的消息全部保存
[capture]
schema_version = 1.0.0
; 留空按模式使用 stereo、stereo_imu 或 imu。
dataset_name =
resolution = 3840x2160
save_rate_hz = 5
duration_s = 60
imu_topic = /imu/data
```

配置书写规则：

- 文件保存为 UTF-8（可带 BOM）；值不加引号，例如 `imu_topic = /imu/data`。
- 注释单独以 `;` 或 `#` 起行，不在参数值后面追加注释。
- 只允许 `[capture]` 段，必须写 `schema_version = 1.0.0`；不接受 `[DEFAULT]` 参数、其他段、重复键或未知键。
- 不做插值；`%`、`${...}` 按字面处理，不展开环境变量。
- 旧自定义 YAML/JSON 配置须按上述结构转换内容，不能只把扩展名改为 `.ini`。

INI 与采集输出的数据契约相互独立；manifest 写入与校验不依赖 PyYAML。`imu_preroll_s`、`imu_postroll_s` 以及作为空消息回退值的 `imu_frame_id` 均可在完整参考 INI 中查看。

## 11. 数据目录状态

`--output` 是输出根目录，默认值为 `./data`。每次启动录制时使用设备本地时间自动创建：

```text
<output>/<dataset_name>_YYMMDD_hhmm/
```

前缀可由 `--dataset-name` 或 INI `dataset_name` 设置，允许 1–64 个 ASCII 字母、数字、下划线或连字符，首字符为字母或数字；默认双目 `stereo`、Camera–IMU `stereo_imu`、独立 IMU `imu`。

例如 `camera-imu --output ./data` 在 2026-09-07 15:30:00 启动时，正式数据集为 `./data/stereo_imu_260907_1530/`。相同前缀同一分钟重复启动且目录已存在时会报错，不会覆盖。会话目录有三种状态：

- `<output>/<dataset_name>_YYMMDD_hhmm.inprogress`：正在录制或进程异常退出后留下的暂存目录；
- `<output>/<dataset_name>_YYMMDD_hhmm`：正常完成并通过结构校验的正式数据集；
- `<output>/<dataset_name>_YYMMDD_hhmm.failed`：采集失败、错误分辨率、格式错误、同步失败或触发数量未完成时保留的现场数据。

不要直接删除 `.failed` 或 `.inprogress`。先检查其中的 `meta/validation.json` 和 `meta/session.json`。

正式数据集结构：

```text
dataset.yaml
cameras/cam0/timestamps.csv
cameras/cam0/<timestamp_ns>.bmp
cameras/cam1/timestamps.csv
cameras/cam1/<timestamp_ns>.bmp
imu/imu0.csv                 # 仅 camera-imu
meta/capture_dataset.yaml
meta/pairs.csv
meta/imu_full.jsonl          # 仅 camera-imu，bag 导出辅助信息
meta/session.json
meta/validation.json
```

其中 `cam0` 永远是左目，`cam1` 永远是右目。JPEG 模式图像扩展名为 `.jpg`。`stereo-triggered` 和 `stereo-continuous` 不再创建 `imu/` 或 IMU JSONL，根 manifest 使用 `imus: []`。联合采集仅保留一份 IMU CSV。Kalibr 不需要的辅助文件（含校验报告）统一放在 `meta/`。

根 `dataset.yaml` 声明字符串 `schema_version: "1.0.0"`、`type: kalibr_directory_dataset`、`dataset_id` 和传感器列表。相机必需 `id/topic/timestamps/images`，IMU 必需 `id/topic/data`；另写 frame ID、时钟源、相机分辨率与 IMU 单位。内部采集 manifest、session、validation 和原始消息 JSONL 都使用同一版本，以 kind 区分；session 标记 `dataset_manifest: kalibr_directory_dataset`、`capture_layout: compact`。根 IMU frame ID 是有效坐标系，JSONL 保留原始 frame ID。

根文件采用 JSON 花括号排版，这是 YAML 的合法子集，可被 Kalibr 直接读取；内部采集文件仍使用 YAML 块排版，二者写入均无需 PyYAML。

`imu/imu0.csv` 直接使用 `timestamp_ns,wx,wy,wz,ax,ay,az` 表头，根 manifest 直接引用它；不生成第二份 CSV，不变更原始数值或时间戳。联合采集的 `meta/imu_full.jsonl` 保留完整消息供 bag 导出，Kalibr 不读取它。图像和相机时间戳表原位复用，无须创建额外的 `images/` 子目录。

本工具只校验和导出新 v1.0.0 数据，不兼容旧整数 schema 1/2/3 或旧双 CSV 布局；不迁移、改名、覆盖或删除已有数据。不新增逐帧 SHA-256 或 PNG 采集输出。

## 12. 离线校验

普通校验：

```bash
python3 script/calibration_data.py validate \
  ./data/stereo_imu_260907_1530
```

校验检查 BMP 文件头、调色板、尺寸及文件长度，左右图片与 CSV 的对应关系、IMU 内容一致性和时间戳。数据文件不计算 SHA-256，已移除 `--verify-checksums` 参数。等长度像素位错误不会被检测，但截断、缺图、错误尺寸及时间倒退仍为硬错误。

新格式还核对根 Kalibr manifest 与内部采集 manifest、IMU CSV/JSONL 一致性、有效 frame ID 及 IMU 前后覆盖。缺少必需 manifest 或联合采集的 IMU 文件属于硬错误。旧版双 CSV 目录明确拒绝，不自动迁移。覆盖报告基于实际保存图像首尾时间，少于设置的正数要求为硬错误；`0` 只关闭额外覆盖要求，不关闭共同窗口检查。

`meta/validation.json` 状态说明：

- `pass`：没有错误或质量警告；
- `warning`：结构可用，但存在源序号缺口、低频率、队列丢弃等质量问题；
- `fail`：存在单侧缺失、损坏文件、错误分辨率、非 NV12、时间倒退、同步超限、无 IMU 或时钟域不一致等硬错误。

正式交付和 bag 导出前应处理所有 `fail`，并评估每一条 `warning`。

## 13. Kalibr 输入与 ROS1 bag

### 直接读取新目录

新采集完成且校验通过的目录可直接作为 `kalibr-noros` task 的目录输入，不必先导出 bag。双目相机 task 中以下片段按传感器 ID 读取：

```yaml
dataset:
  type: directory
  path: /path/to/data/<dataset_name>_YYMMDD_hhmm
cameras:
  - {id: cam0, model: pinhole-equi}
  - {id: cam1, model: pinhole-equi}
calibration:
  synchronization_tolerance_s: 0.0002
```

这只是完整 task 的一部分，还需真实标定板及相应标定参数。目录任务通过 ID 关联根 manifest，不需要 topic，IMU 噪声配置不需要 rostopic。路径只在 dataset.yaml 中声明一次。相对 `dataset.path` 以 task 文件目录为基准；manifest 内部路径则以数据集根目录为基准。bag 输入仍需 topic/rostopic。

`synchronization_tolerance_s` 是双目相机 task 的同步容差，不要加到 dataset manifest，也不是 Camera–IMU 的通用参数。目录 reader 接受 BMP/JPEG；结构读取成功不代表已经完成角点检测或证明标定精度，仍需评估实际检测率、重投影误差及可观性。

### PC 离线导出 ROS1 bag

默认话题：

```text
/stereo/left/image_raw
/stereo/right/image_raw
/imu/data
```

默认不压缩：

```bash
python3 script/calibration_data.py export-ros1 \
  ./data/stereo_imu_260907_1530 \
  ./data/stereo_imu_260907_1530.bag
```

使用 LZ4 或 BZ2：

```bash
python3 script/calibration_data.py export-ros1 \
  ./data/stereo_imu_260907_1530 \
  ./data/stereo_imu_260907_1530_lz4.bag \
  --compression lz4
```

覆盖话题名称：

```bash
python3 script/calibration_data.py export-ros1 \
  ./data/stereo_imu_260907_1530 \
  ./data/stereo_imu_260907_1530.bag \
  --left-topic /cam0/image_raw \
  --right-topic /cam1/image_raw \
  --imu-topic /imu0
```

导出器会先校验目录数据集，完成后重新打开 bag，核对消息类型、数量、首尾时间戳、单调性，以及 Header stamp 与 bag record time。默认不允许从硬错误数据集生成 bag。

只接受 v1.0.0 目录，通过原始 IMU CSV/JSONL 导出；`--force-dataset` 不能绕过版本检查。非空原始 frame ID 保留，只有空 frame ID 才采用会话有效坐标系回退；不修改目录中保存的原始 JSONL。

`--force-dataset` 只用于诊断损坏数据，不能用于正式交付。

## 14. 常见故障处理

### 找不到 AX 运行库

错误通常包含 `libax_sys.so`、`libax_interpreter.so`、`libax_engine.so` 或 `libax_proton.so`。检查：

```bash
ls -l /soc/lib/libax_sys.so \
  /soc/lib/libax_interpreter.so \
  /soc/lib/libax_engine.so \
  /soc/lib/libax_proton.so
```

如运行库在其他目录，使用：

```bash
python3 script/calibration_data.py probe \
  --ax-lib-dir /path/to/ax/libs
```

运行库位于 `/soc/lib` 时先确认环境：

```bash
export BSP_MSP_DIR=/soc/lib
export LD_LIBRARY_PATH=/soc/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}
```

只设置 `BSP_MSP_DIR` 不会改变动态加载器的搜索路径；`libax_engine.so: cannot open shared object file` 通常表示缺少第二行。

### SDK 头文件哈希或 ABI 不一致

不要关闭检查。确认传入的是同一套最新 SDK 的完整 `include` 目录，并核对相机板运行库版本。SDK 更新后需要重新审核 ctypes 结构和函数签名。

### 分辨率不一致

`VIN resolution is ... expected ...` 表示相机 config 与命令不一致。修改上游相机 config 或正确设置 `--resolution`，脚本本身不会重配管线。

### 图像格式不是 NV12

检查 VIN channel 配置。正式标定路径不会自动接受 NV21、RGB 或 vis 的 YUV400 输出。

### 左右同步超过 200 µs

先用 `probe --samples 50` 查看 `stereo_delta_us`、源帧率和序号缺口。确认两路相机同步、上游无阻塞，并确保没有其他消费者竞争同一 VIN 队列。

### 收不到 IMU

检查 ROS 2 环境和话题：

```bash
ros2 topic list
ros2 topic hz /imu/data
ros2 topic echo /imu/data --once
```

确认 `header.stamp` 非零且严格递增，并确认发布端 QoS 能与 BEST_EFFORT 订阅兼容。

### 相机与 IMU 时间差超过 5 秒

说明两者可能不在同一时间域。必须修复 AX PTS 或 IMU `header.stamp` 的时间基准，不能用回调到达时间替换源时间戳。

### 写盘队列丢弃

查看 `meta/session.json` 中的 `writer_queue_drop_pairs`。可更换更快存储、降低 `--save-rate-hz` 或改用 1080p。丢弃以完整双目对为单位，但过多丢弃会降低标定数据质量。

## 15. 交付检查清单

正式交给 Kalibr 前确认：

1. `probe` 在实际分辨率下通过。
2. 左 pipe 2、右 pipe 0、chn 0，左右均为 NV12。
3. 双目最大时间差不超过 200 µs（含边界）。
4. 双目标定触发数据恰好达到要求姿态数，左右数量一致。
5. 双目–IMU 数据有共同时间窗口，IMU 有效频率合理，新采集前后覆盖满足配置且有效 frame ID 一致。
6. 数据目录不是 `.inprogress` 或 `.failed`。
7. `validate` 没有结构或时序硬错误。
8. 已阅读并评估所有质量警告。
9. 直接目录输入使用新根严格 manifest；若交付 ROS1 bag，则导出回读结果为 `pass`。
10. 分别由 Kalibr 的双目和相机–IMU 标定入口实际加载确认；本工具的 reader 集成测试只验证格式，不代替实际标定验收。

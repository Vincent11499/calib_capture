# 双目及双目–IMU 标定数据采集使用操作说明

## 1. 工具用途

本工具用于：

- 逐姿态采集双目标定图像；
- 定时连续采集双目图像；
- 连续采集双目图像及完整 IMU 消息；
- 校验目录数据集的图像、时间戳、同步、频率和完整性；
- 将目录数据集离线导出为 ROS1 `.bag`。

采集入口为：

```text
Q:\project\kalibr_cedarobo\script\calibration_data.py
```

板端使用时，应复制整个 `script` 目录，不能只复制入口文件。

## 2. 已确认的相机接口

| 模式 | 输出 | 左目 | 右目 | 接口 | 格式与分辨率 |
|---|---|---|---|---|---|
| cali | VIN | pipe 2 / chn 0 | pipe 0 / chn 0 | `AX_VIN_GetYuvFrame` | NV12；跟随相机 config，正式标定使用 3840×2160 或 1920×1080 |
| vis | VIN | pipe 2 / chn 0 | pipe 0 / chn 0 | `AX_VIN_GetYuvFrame` | NV12，3840×2160 |
| vis | IVPS | grp 7 / chn 0 | grp 8 / chn 0 | `AX_IVPS_GetChnFrame` | 灰度，640×384 |

本工具的标定录制命令读取 cali VIN 输出，不读取 vis 的 640×384 IVPS 输出。

## 3. 开始前检查

开始采集前确认：

1. 相机服务已经根据所需 config 启动 VIN 输出。
2. 左目为 pipe 2/chn 0，右目为 pipe 0/chn 0。
3. 输出格式为 NV12。
4. 输出分辨率为 3840×2160 或 1920×1080。
5. `/soc/lib/libax_sys.so`、`libax_interpreter.so`、`libax_engine.so` 和 `libax_proton.so` 存在；脚本按依赖顺序显式加载这些现有库。
6. 没有其他程序同时消费相同的 VIN pipe/chn 队列。
7. 输出磁盘有足够空间，输出根目录可写；程序生成的时间戳会话目录尚不存在。
8. 采集双目–IMU 数据时，ROS 2 的 `/imu/data` 正在发布，消息时间戳有效。

典型图像数据量约为：

| 模式 | 4K | 1080p |
|---|---:|---:|
| 默认连续 5 Hz、60 秒、双目 | 约 5 GB | 约 1.25 GB |
| 触发保存 20 对 | 约 0.33 GB | 约 0.08 GB |

程序会提示预计数据量，但不会因为剩余容量或写速不足而拒绝启动。

## 6. 首次硬件探测

### 6.1 探测 4K 双目

相机 config 输出 3840×2160 时执行：

```bash
python3 script/calibration_data.py probe --samples 50
```

默认值等价于：

```bash
python3 script/calibration_data.py probe --samples 50 \
  --left-pipe 2 --left-chn 0 \
  --right-pipe 0 --right-chn 0 \
  --resolution 3840x2160
```

### 6.2 探测 1080p 双目

相机 config 输出 1920×1080 时必须显式指定：

```bash
python3 script/calibration_data.py probe --samples 50 \
  --resolution 1920x1080
```

`--resolution` 不会改变相机输出，只负责校验。实际输出不匹配时程序立即失败。

两种分辨率具体由以下代码共同支持：

- `script/calib_capture/cli.py`：提供 `--resolution WIDTHxHEIGHT`；
- `script/calib_capture/config.py`：`parse_resolution()` 只接受 `3840x2160` 和 `1920x1080`；
- `script/calib_capture/axera.py`：`validate_frame_metadata()` 对 `AX_VIN_GetYuvFrame` 返回帧的实际宽高逐帧校验；
- `script/calib_capture/validator.py`：离线检查 BMP 尺寸是否与会话配置一致。

因此“支持”表示脚本能够接收、采集并校验这两种上游输出，并不表示脚本会修改相机 config。

### 6.3 同时探测 IMU

```bash
source /opt/ros/humble/setup.bash
python3 script/calibration_data.py probe --samples 50 --with-imu \
  --imu-topic /imu/data
```

重点检查 JSON 输出中的：

- `status`：应为 `pass`，允许评估后接受 `warning`，不能忽略 `fail`；
- `mapping`：左目 pipe 2、右目 pipe 0、chn 0；
- `actual_resolution`：与相机 config 和命令一致；
- `observed_formats`：左右均应为 NV12；
- `source_rate_hz`：应接近相机预期 50 Hz；
- `stereo_delta_us.maximum`：不得超过 2000 µs；
- `source_sequence`：检查序号缺口或回退；
- `imu.effective_rate_hz`：应接近 100 Hz；
- `imu.startup_camera_offset_ns`：默认不得超过 5 秒；
- `imu.common_time_window_ns`：应大于 0。

`probe` 未通过时不要直接开始正式标定采集。

## 7. 逐姿态双目标定采集

默认采集 20 个姿态，每次按 Enter 保存一对图像。`--output` 默认是 `./data`，以下显式写出便于说明：

```bash
python3 script/calibration_data.py stereo-triggered --output ./data
```

操作步骤：

1. 将标定板放在第一个姿态，确保左右相机都能清晰看到。
2. 静止后按 Enter。
3. 等待当前双目对写盘完成。
4. 改变标定板的位置、距离、俯仰、偏航和滚转角度。
5. 重复直至保存 20 对。

可指定姿态数量或 1080p：

```bash
python3 script/calibration_data.py stereo-triggered \
  --output ./data \
  --resolution 1920x1080 \
  --poses 20
```

输入 `q`、`quit` 或 `exit` 会中止采集。未完成指定姿态数量时，已采数据保留为 `<output>/<时间戳>.failed`，不会删除。

## 8. 连续双目采集

默认持续 60 秒，按相机 PTS 保存双目 5 Hz（约 200 ms 一对）：

```bash
python3 script/calibration_data.py stereo-continuous \
  --output ./data \
  --duration-s 60 \
  --save-rate-hz 5
```

1080p 示例：

```bash
python3 script/calibration_data.py stereo-continuous \
  --output ./data \
  --resolution 1920x1080 \
  --duration-s 60 \
  --save-rate-hz 5
```

`--save-rate-hz 5` 可省略。限频以首对 PTS 为起点，选择到达每个目标时刻的第一对。例如源周期为 20 ms，指定 6 Hz 时，相对保存时间为 0、180、340、500、680、840、1000 ms；长期平均接近 6 Hz，图像保留各自原始 PTS。

写盘队列满时会丢弃完整双目对，并在 `meta/session.json` 与 `validation.json` 中记录 `writer_queue_drop_pairs`；不会只保存一侧。

当前 BMP 保持原 bottom-up 格式，按大块写入。所有数据文件均不计算 SHA-256，停止录制后也不补算。`meta/session.json` 的 `write_performance` 中记录 `mean_pair_ms`、`max_pair_ms` 和 `total_pair_write_s`，分别表示每对平均、最大和累计写入耗时；包括 BMP、重命名及 CSV 更新，不包含取帧、队列等待或 `fsync`。

### 8.1 按源图像帧分频

`--frame-divisor N` 依据左右帧的 AX `u64SeqNum` 源序号分频。第一对立即保存；以后只有当左右源序号相对上一保存对都至少前进 N 时才保存。跳过操作发生在物理内存映射和 BMP 写盘之前，左右目始终成对处理。

假设 `AX_VIN_GetYuvFrame` 每 20 ms 返回一张：

| 参数 | 保存周期 | 约等于保存频率 |
|---|---:|---:|
| `--frame-divisor 1` | 20 ms | 50 Hz |
| `--frame-divisor 3` | 60 ms | 16.67 Hz |
| `--frame-divisor 5` | 100 ms | 10 Hz |

例如每 3 对保存一对：

```bash
python3 script/calibration_data.py stereo-continuous \
  --output ./data \
  --duration-s 60 \
  --frame-divisor 3
```

`--save-rate-hz` 与 `--frame-divisor` 互斥，推荐使用前者指定目标 Hz；后者适用于固定源周期的整数分频。两者都省略时默认使用 `save_rate_hz: 5`。命令行策略覆盖 YAML；YAML 同一层不能同时设置 `save_rate_hz` 和正数 `frame_divisor`，`frame_divisor: 0` 表示关闭分频。源帧缺失或写盘队列丢对会使实际保存间隔变长，相关统计写入 `meta/session.json`。

参数作用域：

| 参数 | 可用命令 | 作用 |
|---|---|---|
| `--samples N` | 仅 `probe` | 连续观察 N 个同步双目对，只做诊断、不落盘 |
| `--save-rate-hz HZ` | `stereo-continuous`、`camera-imu` | 按 PTS 保存接近指定频率的双目对 |
| `--frame-divisor N` | `stereo-continuous`、`camera-imu` | 左右 AX 源序号都至少前进 N 后保存一对 |

逐姿态 `stereo-triggered` 由操作者按 Enter 决定保存时机，不使用上述三个参数。

## 9. 双目–IMU 联合采集

确认相机和 IMU 探测通过后执行：

```bash
source /opt/ros/humble/setup.bash
python3 script/calibration_data.py camera-imu \
  --output ./data \
  --duration-s 60 \
  --save-rate-hz 5 \
  --imu-topic /imu/data
```

`camera-imu` 默认保存双目 5 Hz，限频只作用于完整双目对。IMU 收到的消息全部保存，不随图像降频。

IMU 默认 QoS 为：

```text
BEST_EFFORT + VOLATILE + KEEP_LAST(depth=2000)
```

相机使用各自 `u64PTS × 1000` 纳秒，IMU 使用原始 `header.stamp`。启动时两者首帧时间差超过 5 秒会拒绝录制。

## 10. 使用 YAML 配置

模板位于 `script/default_config.yaml`。注意：`--config` 是主命令参数，必须写在子命令之前。

正确示例：

```bash
python3 script/calibration_data.py --config script/default_config.yaml camera-imu \
  --output ./data \
  --resolution 1920x1080
```

错误示例：

```bash
python3 script/calibration_data.py camera-imu --config script/default_config.yaml
```

配置优先级为：

```text
命令行参数 > YAML capture 配置 > 程序内置默认值
```

`hardware_layout` 仅记录 cali/vis 接线清单；采集参数从 YAML 的 `capture` 段读取。

## 11. 数据目录状态

`--output` 是输出根目录，默认值为 `./data`。每次启动录制时使用设备本地时间自动创建：

```text
<output>/YYYY-MM-DD_HH-MM-SS/
```

例如 `--output ./data` 在 2026-09-07 15:30:00 启动时，正式数据集为 `./data/2026-09-07_15-30-00/`。同一秒重复启动且目录已存在时会报错，不会覆盖。会话目录有三种状态：

- `<output>/<时间戳>.inprogress`：正在录制或进程异常退出后留下的暂存目录；
- `<output>/<时间戳>`：正常完成并通过结构校验的正式数据集；
- `<output>/<时间戳>.failed`：采集失败、错误分辨率、格式错误、同步失败或触发数量未完成时保留的现场数据。

不要直接删除 `.failed` 或 `.inprogress`。先检查其中的 `validation.json` 和 `meta/session.json`。

正式数据集结构：

```text
dataset.yaml
cameras/cam0/timestamps.csv
cameras/cam0/<timestamp_ns>.bmp
cameras/cam1/timestamps.csv
cameras/cam1/<timestamp_ns>.bmp
imu/imu0.csv
meta/pairs.csv
meta/imu_full.jsonl
meta/session.json
validation.json
```

其中 `cam0` 永远是左目，`cam1` 永远是右目。新数据集为 schema 2，标记 `data_integrity: structural`，不生成校验和清单；读取时兼容 schema 1 的旧数据，忽略旧清单。

## 12. 离线校验

普通校验：

```bash
python3 script/calibration_data.py validate \
  ./data/2026-09-07_15-30-00
```

校验检查 BMP 文件头、调色板、尺寸及文件长度，左右图片与 CSV 的对应关系、IMU 内容一致性和时间戳。数据文件不计算 SHA-256，已移除 `--verify-checksums` 参数。等长度像素位错误不会被检测，但截断、缺图、错误尺寸及时间倒退仍为硬错误。

`validation.json` 状态说明：

- `pass`：没有错误或质量警告；
- `warning`：结构可用，但存在源序号缺口、低频率、队列丢弃等质量问题；
- `fail`：存在单侧缺失、损坏文件、错误分辨率、非 NV12、时间倒退、同步超限、无 IMU 或时钟域不一致等硬错误。

正式交付和 bag 导出前应处理所有 `fail`，并评估每一条 `warning`。

## 13. 导出 ROS1 bag

默认话题：

```text
/stereo/left/image_raw
/stereo/right/image_raw
/imu/data
```

默认不压缩：

```bash
python3 script/calibration_data.py export-ros1 \
  ./data/2026-09-07_15-30-00 \
  ./data/2026-09-07_15-30-00.bag
```

使用 LZ4 或 BZ2：

```bash
python3 script/calibration_data.py export-ros1 \
  ./data/2026-09-07_15-30-00 \
  ./data/2026-09-07_15-30-00_lz4.bag \
  --compression lz4
```

覆盖话题名称：

```bash
python3 script/calibration_data.py export-ros1 \
  ./data/2026-09-07_15-30-00 \
  ./data/2026-09-07_15-30-00.bag \
  --left-topic /cam0/image_raw \
  --right-topic /cam1/image_raw \
  --imu-topic /imu0
```

导出器会先校验目录数据集，完成后重新打开 bag，核对消息类型、数量、首尾时间戳、单调性，以及 Header stamp 与 bag record time。默认不允许从硬错误数据集生成 bag。

`--force-dataset` 只用于诊断损坏数据，不能用于正式交付。

## 14. 常见故障处理

### 找不到 AX 运行库

错误通常包含 `libax_sys.so`、`libax_interpreter.so`、`libax_engine.so` 或 `libax_proton.so`。检查：

```bash
ls -l /soc/lib/libax_sys.so \
  /soc/lib/libax_interpreter.so \
  /soc/lib/libax_engine.so \
  /soc/lib/libax_proton.so
```

如运行库在其他目录，使用：

```bash
python3 script/calibration_data.py probe \
  --ax-lib-dir /path/to/ax/libs
```

运行库位于 `/soc/lib` 时先确认环境：

```bash
export BSP_MSP_DIR=/soc/lib
export LD_LIBRARY_PATH=/soc/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}
```

只设置 `BSP_MSP_DIR` 不会改变动态加载器的搜索路径；`libax_engine.so: cannot open shared object file` 通常表示缺少第二行。

### SDK 头文件哈希或 ABI 不一致

不要关闭检查。确认传入的是同一套最新 SDK 的完整 `include` 目录，并核对相机板运行库版本。SDK 更新后需要重新审核 ctypes 结构和函数签名。

### 分辨率不一致

`VIN resolution is ... expected ...` 表示相机 config 与命令不一致。修改上游相机 config 或正确设置 `--resolution`，脚本本身不会重配管线。

### 图像格式不是 NV12

检查 VIN channel 配置。正式标定路径不会自动接受 NV21、RGB 或 vis 的 YUV400 输出。

### 左右同步超过 2 ms

先用 `probe --samples 50` 查看 `stereo_delta_us`、源帧率和序号缺口。确认两路相机同步、上游无阻塞，并确保没有其他消费者竞争同一 VIN 队列。

### 收不到 IMU

检查 ROS 2 环境和话题：

```bash
ros2 topic list
ros2 topic hz /imu/data
ros2 topic echo /imu/data --once
```

确认 `header.stamp` 非零且严格递增，并确认发布端 QoS 能与 BEST_EFFORT 订阅兼容。

### 相机与 IMU 时间差超过 5 秒

说明两者可能不在同一时间域。必须修复 AX PTS 或 IMU `header.stamp` 的时间基准，不能用回调到达时间替换源时间戳。

### 写盘队列丢弃

查看 `meta/session.json` 中的 `writer_queue_drop_pairs`。可更换更快存储、降低 `--save-rate-hz` 或改用 1080p。丢弃以完整双目对为单位，但过多丢弃会降低标定数据质量。

## 15. 交付检查清单

正式交给 Kalibr 前确认：

1. `probe` 在实际分辨率下通过。
2. 左 pipe 2、右 pipe 0、chn 0，左右均为 NV12。
3. 双目最大时间差不超过 2000 µs。
4. 双目标定触发数据恰好达到要求姿态数，左右数量一致。
5. 双目–IMU 数据有共同时间窗口，IMU 有效频率合理。
6. 数据目录不是 `.inprogress` 或 `.failed`。
7. `validate` 没有结构或时序硬错误。
8. 已阅读并评估所有质量警告。
9. ROS1 bag 导出回读结果为 `pass`。
10. 分别由 Kalibr 的双目和相机–IMU 标定入口实际加载确认。
